= Concept: Authentication and Profile Management
:toc: left

This document outlines the flows for registration, login, and profile management in PantryPal, considering both local-only and remote-sync scenarios.

== Core Principles
* **Unique Identifiers:** Both `username` and `email` must be unique across the entire system (local and remote). Login supports both identifiers.
* **Identity Provider (IdP):** Keycloak is used as the primary IdP for remote accounts.
* **Server Database:** The server maintains its own `profiles` table to store metadata and link Keycloak users to application data.
* **Local First:** Every profile is primarily a local entity. It has a local password (hashed) for device access.
* **Decoupled Passwords:** A remote-linked profile has two passwords:
    1. **Local Password:** Used to unlock the app on the specific device.
    2. **Remote Password:** Used to authenticate against the server (Keycloak).
    * These can differ (e.g., if the remote password was changed on another device).
* **Profile-Specific Server:** The server address (`serverUrl`) is stored per profile. There is no global server setting.

== Login States
The system distinguishes between three primary profile states:

1. **Local-Only Profile**:
    * `serverId` is null.
    * `serverUrl` is null.
    * Synchronization is disabled.
2. **Remote Profile (Logged In Remotely)**:
    * `serverId` is present.
    * `serverUrl` is present.
    * `isLoggedInRemotely` is true (valid JWT available).
    * Background synchronization is enabled.
3. **Remote Profile (Logged In Locally)**:
    * `serverId` is present.
    * `serverUrl` is present.
    * `isLoggedInRemotely` is false.
    * User has access to local data but cannot synchronize until a **Remote Login** is performed.
    * This state occurs if the user logs in with their local password or if the remote session expires.

== Registration Flow

=== 1. Local-Only Registration
1. User enters username, email, and password.
2. Client creates `ProfileEntity` with a new `id`, `passwordHash` (local), `serverId = null`, and `serverUrl = null`.
3. User is logged into the local profile.

=== 2. Remote Registration (New Profile)
1. User enters username, email, password, and **Server URL**.
2. **Remote Call:** Client calls `/register` on the specified `serverUrl`.
3. **Server Actions:** Create user in Keycloak and server DB; return `serverId` and tokens.
4. **Local Persistence:** Client creates `ProfileEntity` with `serverId`, `serverUrl`, and local `passwordHash`.

== Upgrading a Local Profile to Remote
A user who started with a local-only profile can later decide to enable synchronization.

=== Option A: Link to Existing Remote Account
1. User provides **Server URL** and **Remote Credentials**.
2. Client calls `/login` on that server.
3. On success, the client updates the local `ProfileEntity`:
    * Sets `serverId` from response.
    * Sets `serverUrl`.
    * (Optional) Prompts to update local password to match remote.

=== Option B: Create New Remote Account
1. User provides **Server URL** and **Credentials**.
2. Client calls `/register` on that server.
3. On success, the client updates the local `ProfileEntity` with `serverId` and `serverUrl`.

== Login Flow

=== 1. Local Login (Unlock Device)
1. User selects a profile and enters their **Local Password**.
2. Client verifies password against the local `passwordHash`.
3. If valid, the app is unlocked. `isLoggedInRemotely` remains `false`.

=== 2. Remote Login (Enable Sync)
1. User enters their **Remote Password**.
2. **Server Call:** Client calls `/login` on the profile's `serverUrl`.
3. **Success:** Client stores tokens and sets `isLoggedInRemotely = true`.

== Profile Updates & Synchronization
* Changing the **Local Password** only updates the local `passwordHash`.
* Changing username/email updates the local record and marks it as "pending sync".
* Synchronization requires `isLoggedInRemotely = true`.

== Profile Deletion
* **Local Only:** Deletes the profile and data from the device.
* **Remote:** Deletes from Keycloak and marks as deleted on the server.
